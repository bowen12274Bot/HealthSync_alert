# 伺服器端長期預警分析規則

## 1. 文件目的

本文定義伺服器端長期預警分析規則，作為長期分析排程、分析模組、`long_term_alerts` 寫入邏輯與後續 API 設計的共同依據。

本文件處理的範圍包含：

- 伺服器端長期預警的定位
- 長期分析週期與執行時機
- 整體趨勢分析規則
- 預警歷史模式分析規則
- 風險分數計算方式
- 長期預警成立與寫入條件

本文件不處理的範圍包含：

- 手機端即時預警分析規則
- 手機端資料同步實作細節
- 趨勢報表 API 輸出格式
- 醫療診斷或疾病判定邏輯

本文件的核心目標如下：

- 讓伺服器依歷史資料定期判斷是否存在長期風險
- 只在風險達門檻時產生 `long_term_alerts`
- 不保存每一次分析過程的完整中間結果

## 2. 長期預警的定位

本系統的本地預警與長期預警責任不同。

可用以下方式理解：

```text
本地預警 = 判斷當下是否危險
長期預警 = 判斷最近一段時間是否已形成長期風險
```

因此：

- 本地預警由手機端負責
- 長期預警由伺服器端負責
- 長期預警不重做即時危險判斷
- 長期預警以已同步進伺服器的歷史資料為唯一分析依據

本階段長期預警不直接提供使用者閱讀完整分析結果，而是：

- 定期掃描伺服器資料
- 計算長期風險分數
- 只有在風險成立時，才寫入 `long_term_alerts`

## 3. 分析資料來源

本階段長期預警分析使用以下兩類資料：

```text
1. 週期健康紀錄表 periodic_health_record
2. 預警歷史表 alert_history
```

對應用途如下：

| 資料表 | 主要用途 |
| --- | --- |
| `periodic_health_record` | 用於整體趨勢分析 |
| `alert_history` | 用於預警歷史模式分析 |

補充原則如下：

- `daily_health_summary` 目前不作為第一版長期預警的必要依據
- `activity_baseline_profile` 目前不作為第一版長期預警核心判定依據

原因如下：

```text
periodic_health_record 是目前已明確可穩定同步到伺服器的長期健康資料主體。
alert_history 是目前已明確可穩定同步到伺服器的完整預警事件歷史。
```

此外，雖然伺服器端保有 `activity_baseline_profile`，但由於目前 `periodic_health_record` 不保證能穩定提供可直接對位的活動等級分析欄位，因此本階段不將其作為長期預警核心判斷條件。

## 4. 分析週期與執行時機

本階段長期預警固定分成兩種分析週期：

```text
1. 7 天分析
2. 30 天分析
```

執行時機如下：

- `7 天分析`：每週日執行一次
- `30 天分析`：每月最後一天執行一次

可理解為：

```text
週分析 = 掃描最近 7 天資料
月分析 = 掃描最近 30 天資料
```

本階段不採用：

- 每日滾動分析後全部落庫
- 每次查詢時才即時計算所有長期預警結果

原因如下：

- 長期預警本質上不需要高頻更新
- 固定週期分析可降低資料量與複雜度
- 分析結果只在成立時寫入 `long_term_alerts`，較符合本系統定位

## 5. 長期預警分析模組

本階段伺服器端長期預警分成兩個分析模組：

```text
1. 整體趨勢分析
2. 預警歷史模式分析
```

兩者之間的關係如下：

- 兩個模組各自獨立計算風險分數
- 兩個模組各自獨立判斷是否成立長期預警
- 不先將兩個模組硬合成同一個總分

也就是：

```text
整體趨勢分析成立
=> 可產生一筆趨勢型長期預警

預警歷史模式分析成立
=> 可產生一筆歷史模式型長期預警
```

## 6. 風險等級設計

本階段長期預警風險等級與本地預警語彙保持一致，統一使用：

```text
無
觀察
注意
警戒
```

但本階段長期預警的 `risk_score` 不使用本地端 `0~7` 的離散分數，而改用：

```text
0 ~ 100
```

原因如下：

- 長期風險較適合用連續分數描述
- 長期分析涉及多項證據，不適合硬切成少量離散分數
- 連續分數較容易後續微調權重與門檻

對應等級如下：

| risk_score | 風險等級 |
| ---: | --- |
| 0 ~ 39 | 無 |
| 40 ~ 59 | 觀察 |
| 60 ~ 79 | 注意 |
| 80 ~ 100 | 警戒 |

補充原則如下：

- `無`：表示目前無足夠證據支持長期風險
- `觀察`：表示已有一定異常訊號，但不足以寫入 `long_term_alerts`
- `注意`：表示已具備長期風險成立條件
- `警戒`：表示風險程度高，且證據較集中或較持續

## 7. 長期預警成立條件

本階段長期預警的寫入門檻如下：

```text
risk_score < 60
=> 不寫入 long_term_alerts

risk_score >= 60
=> 寫入 long_term_alerts
```

因此可再整理成：

| risk_score | 等級 | 是否寫入 `long_term_alerts` |
| ---: | --- | --- |
| 0 ~ 39 | 無 | 否 |
| 40 ~ 59 | 觀察 | 否 |
| 60 ~ 79 | 注意 | 是 |
| 80 ~ 100 | 警戒 | 是 |

也就是：

- `觀察` 只作為分析過程中的中間判定
- `注意` 與 `警戒` 才視為正式長期預警

## 8. 整體趨勢分析

## 8.1 分析目的

整體趨勢分析用來判斷使用者最近一段時間的整體生理狀態是否有長期風險。

本分析不是單純檢查：

- 哪個指標單次超標

而是綜合判斷：

- 是否存在明顯異常
- 是否偏離個人歷史常態
- 是否在分析期間內反覆出現
- 在 30 天分析中，是否存在慢速惡化

## 8.2 分析指標

本階段整體趨勢分析使用以下三個生理指標：

```text
HR
HRV
SpO2
```

每個指標先計算自己的 `indicator risk`，再合成單次分析的整體趨勢風險分數。

## 8.3 指標風險分數公式

### 8.3.1 7 天分析

對單一指標，7 天分析的風險分數公式如下：

```text
indicator_risk_7d =
100 × (
  0.45 × A
  + 0.35 × P
  + 0.20 × C
)
```

其中：

| 符號 | 意義 |
| --- | --- |
| `A` | 人類標準區間異常 |
| `P` | 個人標準化偏移 |
| `C` | 異常持續性 |

這些值都應先轉成 `0 ~ 1`。

### 8.3.2 30 天分析

對單一指標，30 天分析的風險分數公式如下：

```text
indicator_risk_30d =
100 × (
  0.35 × A
  + 0.30 × P
  + 0.20 × C
  + 0.15 × D
)
```

其中新增：

| 符號 | 意義 |
| --- | --- |
| `D` | 慢速惡化 |

這些值都應先轉成 `0 ~ 1`。

權重設計原則如下：

- `A` 代表絕對異常程度，因此在 7 天分析中權重最高
- `P` 代表相對個人常態的偏離，次於 `A`
- `C` 代表異常是否反覆出現
- `D` 只在 30 天分析啟用，用來補捉慢速惡化

## 8.4 整體趨勢總分公式

三個指標各自得到 `indicator_risk` 後，再計算整體趨勢風險分數：

```text
overall_risk =
0.7 × max(indicator_risks)
+ 0.3 × mean(indicator_risks)
```

也就是：

- `70%` 取最嚴重單一指標
- `30%` 取三個指標的平均

此設計的目的如下：

- 若單一指標非常嚴重，不應被平均稀釋掉
- 若多指標同時中度異常，也應提高整體分數

因此：

```text
整體趨勢分析 = 重視最嚴重單一指標
+ 兼顧多指標共同變差
```

## 8.5 A：人類標準區間異常

`A` 用來表示某指標是否已經偏離一般合理範圍。

此值建議映射為：

```text
無明顯異常 = 0
中度異常 = 0.5
明顯異常 = 1.0
```

### 8.5.1 HR

可使用：

- 分析期間 `avg_hr`
- 分析期間異常高點出現情況

建議映射如下：

```text
avg_hr <= 95
=> A = 0

95 < avg_hr < 100
=> A = 0.5

avg_hr >= 100
=> A = 1.0
```

若分析期間內高心率極值出現次數明顯偏多，例如多筆 `max_hr >= 120`，則可將 `A` 至少提升至：

```text
A >= 0.8
```

### 8.5.2 HRV

HRV 沒有足夠穩定的單一絕對正常值，因此本階段只使用保守觀察線。

建議映射如下：

```text
avg_hrv >= 25
=> A = 0

20 <= avg_hrv < 25
=> A = 0.5

avg_hrv < 20
=> A = 1.0
```

### 8.5.3 SpO2

SpO2 的絕對值意義較明確，因此可相對敏感。

建議映射如下：

```text
avg_spo2 >= 96
=> A = 0

95 <= avg_spo2 < 96
=> A = 0.5

avg_spo2 < 95
=> A = 1.0
```

若分析期間內低血氧極值出現多次，例如多筆 `min_spo2 <= 92`，則可將 `A` 至少提升至：

```text
A >= 0.8
```

## 8.6 P：個人標準化偏移

`P` 用來表示目前分析區間是否已偏離該使用者自己的歷史常態。

本階段使用：

```text
z-score
```

公式如下：

```text
z =
(近期區間平均 - 個人歷史平均) / 個人歷史標準差
```

方向規則如下：

- `HR`：`z` 越大越差
- `HRV`：`z` 越小越差
- `SpO2`：`z` 越小越差

歷史參考區間如下：

- `7 天分析`：使用前 `30 天` 歷史資料
- `30 天分析`：使用前 `90 天` 歷史資料

映射規則建議如下：

```text
未達中度偏移
=> P = 0

中度偏移
=> P = 0.5

明顯偏移
=> P = 1.0
```

可進一步具體化為：

```text
|z| < 1.5
=> P = 0

1.5 <= |z| < 2.0
=> P = 0.5

|z| >= 2.0
=> P = 1.0
```

但實際判斷時仍需依指標方向解讀，例如：

```text
HR 看 z 是否偏大
HRV 看 z 是否偏小
SpO2 看 z 是否偏小
```

## 8.7 C：異常持續性

`C` 用來表示異常並非單次出現，而是在分析期間內反覆存在。

做法如下：

1. 先定義單筆 `periodic_health_record` 是否屬異常週期
2. 再計算分析期間內異常週期占比 `r`
3. 將占比轉成 `0 ~ 1`

### 8.7.1 異常週期定義

本階段建議使用：

```text
HR：
avg_hr > 95
或 max_hr >= 115

HRV：
avg_hrv < 25

SpO2：
avg_spo2 < 95
或 min_spo2 <= 93
```

### 8.7.2 占比映射

令：

```text
r = 異常週期數 / 分析期間總週期數
```

建議映射如下：

```text
r < 0.2
=> C = 0

0.2 <= r < 0.4
=> C = 0.5

r >= 0.4
=> C = 1.0
```

## 8.8 D：慢速惡化

`D` 只在 `30 天分析` 啟用。

目的如下：

```text
補捉沒有快速爆發、
但正在持續往不良方向移動的長期變化
```

本階段建議以兩個條件判定：

```text
1. 最近 30 天區間平均相較前一個 30 天更差
2. 最近 30 天資料序列斜率持續往不良方向移動
```

映射規則建議如下：

```text
未達慢速惡化
=> D = 0

存在輕微慢速惡化
=> D = 0.5

存在明顯慢速惡化
=> D = 1.0
```

方向規則如下：

- `HR`：平均升高、斜率向上為惡化
- `HRV`：平均降低、斜率向下為惡化
- `SpO2`：平均降低、斜率向下為惡化

## 9. 預警歷史模式分析

## 9.1 分析目的

預警歷史模式分析用來判斷預警事件是否已形成反覆、密集或持續的長期風險模式。

本分析不是重做本地預警，而是根據：

- 預警出現得多不多
- 預警風險高不高
- 預警持續時間長不長
- 預警是否集中在短時間爆發

來判斷是否應形成長期預警。

## 9.2 分析面向

本階段預警歷史模式分析使用以下四個面向：

```text
F = 預警次數 frequency
S = 預警嚴重度 severity
D = 預警持續時間 duration
C = 預警集中度 concentration
```

這些值都應先轉成 `0 ~ 1`。

## 9.3 分數公式

### 9.3.1 7 天分析

```text
history_risk_7d =
100 × (
  0.35 × F
  + 0.30 × S
  + 0.20 × D
  + 0.15 × C
)
```

### 9.3.2 30 天分析

```text
history_risk_30d =
100 × (
  0.30 × F
  + 0.30 × S
  + 0.25 × D
  + 0.15 × C
)
```

設計原則如下：

- `F` 代表發作頻率
- `S` 代表事件強度
- `D` 代表事件負擔是否長時間存在
- `C` 代表事件是否集中爆發

30 天分析中，`D` 權重略高，是因為較長周期更適合觀察持續時間負擔。

## 9.4 F：預警次數

`F` 用來表示分析期間內預警出現是否過多。

本階段可取：

- 分析期間總預警次數
- 同一類型預警次數

並使用較高風險者作為 `F` 的依據。

### 9.4.1 7 天映射

```text
0 次
=> F = 0

1 次
=> F = 0.25

2 次
=> F = 0.5

3 次
=> F = 0.75

>= 4 次
=> F = 1.0
```

### 9.4.2 30 天映射

```text
0 ~ 1 次
=> F = 0

2 ~ 3 次
=> F = 0.25

4 ~ 5 次
=> F = 0.5

6 ~ 7 次
=> F = 0.75

>= 8 次
=> F = 1.0
```

## 9.5 S：預警嚴重度

`S` 用來表示分析期間內高風險事件比例是否偏高。

本階段可用：

- 高風險事件次數占比
- 分析期間內是否出現特別嚴重事件

建議映射如下：

```text
無高風險事件
=> S = 0

高風險比例 < 20%
=> S = 0.25

20% <= 比例 < 40%
=> S = 0.5

40% <= 比例 < 60%
=> S = 0.75

比例 >= 60%
=> S = 1.0
```

若期間內存在明顯高優先級事件，可直接將 `S` 提升至至少：

```text
S >= 0.75
```

## 9.6 D：預警持續時間

`D` 用來表示事件對使用者的持續負擔是否偏長。

本階段可同時參考：

- 平均持續時間
- 最長持續時間

並取較高風險者作為 `D` 的依據。

建議映射如下：

```text
平均 < 10 分鐘
且最長 < 20 分鐘
=> D = 0

平均 10 ~ 19 分鐘
或最長 20 ~ 29 分鐘
=> D = 0.25

平均 20 ~ 29 分鐘
或最長 30 ~ 44 分鐘
=> D = 0.5

平均 30 ~ 44 分鐘
或最長 45 ~ 59 分鐘
=> D = 0.75

平均 >= 45 分鐘
或最長 >= 60 分鐘
=> D = 1.0
```

## 9.7 C：預警集中度

`C` 用來表示事件是否集中在短時間內反覆出現。

此指標不是看總數，而是看：

```text
事件是否在少數日期內密集發生
```

建議映射如下：

```text
無明顯集中
=> C = 0

短時間內出現輕度集中
=> C = 0.5

短時間內出現明顯集中爆發
=> C = 1.0
```

例如：

```text
2 天內 2 次
=> 可視為 C = 0.5

2 天內 >= 3 次
或分析期間大部分事件集中在少數日期
=> 可視為 C = 1.0
```

## 10. 長期預警寫入方式

本階段兩個分析模組獨立寫入 `long_term_alerts`。

也就是：

```text
trend_risk_score >= 60
=> 寫入一筆趨勢型長期預警

history_risk_score >= 60
=> 寫入一筆歷史模式型長期預警
```

因此不建議：

- 先把兩個分數相加成單一總分
- 再只寫一筆預警

原因如下：

- 兩個分析模組代表不同風險來源
- 分開寫入較容易解釋觸發原因
- 後續也較容易對應不同前端顯示或後續處理策略

建議在 `long_term_alerts` 至少保存：

- `alert_type`
- `risk_score`
- `trigger_reason`
- `analysis_start`
- `analysis_end`

其中：

- `alert_type` 可區分趨勢型或歷史模式型長期預警
- `trigger_reason` 應描述是哪一類證據促成該次長期預警成立

## 11. 完整分析流程

```text
1. 到達固定分析時機
   - 每週日執行 7 天分析
   - 每月最後一天執行 30 天分析

2. 掃描所有使用者

3. 讀取分析期間內的 periodic_health_record
   - 供整體趨勢分析使用

4. 讀取分析期間內的 alert_history
   - 供預警歷史模式分析使用

5. 執行整體趨勢分析
   a. 對 HR、HRV、SpO2 各自計算 indicator_risk
   b. 依公式合成 overall_risk
   c. 轉成風險等級

6. 執行預警歷史模式分析
   a. 計算 F、S、D、C
   b. 依公式合成 history_risk
   c. 轉成風險等級

7. 判斷是否寫入 long_term_alerts
   - trend_risk_score >= 60 => 寫入趨勢型長期預警
   - history_risk_score >= 60 => 寫入歷史模式型長期預警

8. 若分數未達門檻
   - 不保存額外分析結果
```

## 12. 第一版設計邊界

本階段長期預警先採以下邊界：

- 不保存所有分析過程的完整中間資料
- 不建立專門的長期分析結果表
- 不依賴 `daily_health_summary`
- 不依賴 `activity_level` 對位的個人活動基準比較
- 不做醫療診斷結論

這代表本階段長期預警的目標是：

```text
從已同步的歷史資料中，
定期萃取出足以成立長期風險的證據，
並在達門檻時產生 long_term_alerts。
```

## 13. 核心規則摘要

可用以下幾句話總結本設計：

```text
伺服器端長期預警固定在每週日與每月最後一天執行。
整體趨勢分析主要根據 periodic_health_record 計算 HR、HRV、SpO2 的長期風險分數。
預警歷史模式分析主要根據 alert_history 計算事件次數、嚴重度、持續時間與集中度風險。
兩個分析模組各自獨立計算 risk_score，且只有在 risk_score >= 60 時才寫入 long_term_alerts。
長期預警風險分數採 0~100，並映射為 無 / 觀察 / 注意 / 警戒 四級。
```

最簡短版本如下：

> 伺服器端每週與每月固定掃描 `periodic_health_record` 與 `alert_history`，分別執行整體趨勢分析與預警歷史模式分析，將結果轉成 `0~100` 的長期風險分數；當分數達到 `60` 以上時，才正式寫入 `long_term_alerts`。
