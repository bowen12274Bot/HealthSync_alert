# Server Database Spec

## 1. 這份文件在說什麼

這份文件用來定義伺服器長期資料庫的責任與資料表方向。

## 2. 角色

伺服器長期資料庫負責：

- 保存使用者資料
- 保存使用者活動基準資料
- 保存整理後的健康資料
- 支援長期分析
- 支援歷史查詢與報表

## 3. 資料表

目前伺服器端以七張表為主：

- 使用者帳號表
- 使用者基本資料表
- 使用者活動基準表
- 週期健康紀錄表
- 每日健康摘要表
- 長期預警表
- 預警歷史表

## 4. 使用者帳號表

建議至少包含：

- 帳號編號
- 登入帳號
- 密碼雜湊
- 帳號狀態
- 建立時間
- 最後登入時間

## 5. 使用者基本資料表

建議至少包含：

- 使用者編號
- 帳號編號
- 姓名
- 年齡
- 性別
- 基本健康資訊
- 建立時間

## 6. 使用者活動基準表

這張表用來保存使用者在不同活動等級下的正常生理基準值，提供後續分析模組、預警規則與裝置端資料生成邏輯使用。

每位使用者應有 4 筆資料，分別對應：

- activity_level 0
- activity_level 1
- activity_level 2
- activity_level 3

建議至少包含：

- 活動基準編號
- 使用者編號
- 活動等級
- 目標心率
- 目標心率變異
- 目標血氧
- 更新時間

## 7. 週期健康紀錄表

建議至少包含：

- 週期紀錄編號
- 使用者編號
- 統計開始時間
- 統計結束時間
- 平均心率
- 最低心率
- 最高心率
- 平均心率變異
- 平均血氧
- 最低血氧
- 步數
- 主要活動狀態
- 建立時間

## 8. 每日健康摘要表

建議至少包含：

- 每日摘要編號
- 使用者編號
- 摘要日期
- 平均心率
- 靜止心率
- 平均心率變異
- 平均血氧
- 最低血氧
- 總步數
- 睡眠時長
- 睡眠週期摘要
- 建立時間

## 9. 長期預警表

這張表用來保存伺服器後端基於長期資料分析後產生的長期預警結果，不直接承接手機端同步上傳的預警資料。

建議至少包含：

- 長期預警編號
- 使用者編號
- 預警類型
- 風險分數
- 觸發原因
- 分析開始日期
- 分析結束日期
- 處理狀態
- 建立時間

## 10. 預警歷史表

這張表用來保存來源預警歷史，包含手機端同步上傳的完整預警資料，也可承接其他來源的預警事件歷史。

建議至少包含：

- 預警歷史編號
- 使用者編號
- 預警來源
- 來源預警編號
- 預警類型
- 最高風險分數
- 觸發原因
- 首次發生時間
- 最後異常時間
- 解除時間
- 持續時間
- 狀態變化次數
- 是否曾惡化
- 處理狀態
- 建立時間

補充邊界：

- 手機端同步上來的完整預警資料，應寫入 `預警歷史表`
- `長期預警表` 由伺服器後端長期分析模組依歷史資料另外產生
