# Local Database Spec

## 1. 這份文件在說什麼

這份文件用來定義手機端本地短期資料庫的責任與資料表方向。

## 2. 角色

本地短期資料庫負責：

- 接收高頻即時健康資料
- 支援離線暫存
- 支援本地即時預警
- 保存待同步資料

## 3. 資料表

目前本地端以五張表為主：

- 即時健康資料表
- 週期健康紀錄表
- 即時預警表
- 預警狀態表
- 同步紀錄表

## 4. 即時健康資料表

建議至少包含：

- 即時資料編號
- 心率
- 心率變異
- 血氧
- 活動等級
- 紀錄時間

## 5. 週期健康紀錄表

這張表用來保存本地即時健康資料經過 10 分鐘壓縮後的同步輸出結果。

建議至少包含：

- 週期紀錄編號
- 視窗開始時間
- 視窗結束時間
- 平均心率
- 最低心率
- 最高心率
- 平均心率變異
- 平均血氧
- 最低血氧
- 主要活動等級
- 樣本數
- 同步狀態
- 建立時間

補充：

- 這張表不是原始資料表，而是同步輸出表
- 同一位使用者在同一個 `window_start + window_end` 只能有一筆紀錄
- `window_start + window_end` 可作為同步範圍與去重依據

## 6. 即時預警表

建議至少包含：

- 即時預警編號
- 預警類型
- 初始風險分數
- 觸發原因
- 判斷開始時間
- 判斷結束時間
- 首次發生時間
- 同步狀態

說明：

- `sync_status` 建議落在即時預警主表
- 當預警分析模組判定該預警已形成完整紀錄時，才由此表進入待同步範圍

## 7. 預警狀態表

建議至少包含：

- 預警狀態編號
- 即時預警編號
- 狀態
- 風險分數
- 狀態時間
- 狀態說明

其中：

- 狀態表示該預警事件目前所處的生命週期階段
- 風險分數表示該時間點的風險強度
- `status` 建議統一使用 `觀察中 / 注意 / 警戒 / 恢復中 / 已解除`
- `建立 / 升級 / 降級` 屬於狀態變化語意，不建議直接作為 `status` 欄位值

補充：

- 預警狀態表主要保存生命週期變化歷史
- 不建議在這張表上再承接同步狀態

## 8. 同步紀錄表

建議至少包含：

- 同步紀錄編號
- 同步開始時間
- 同步結束時間
- 同步狀態
- 同步資料範圍
- 同步資料筆數
- 失敗原因
- 重試次數
