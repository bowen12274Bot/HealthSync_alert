# 即時預警顯示設計

## 1. 文件目的

本文定義手機前端「即時預警顯示頁」的設計規則，作為以下內容的共同依據：

- 即時預警頁的畫面結構
- 即時模式與歷史模式的資料邊界
- 頁面入口與導向規則
- 前端風險等級與顏色規則

本文只處理單筆預警顯示頁，不處理：

- 預警歷史列表頁本身
- 預警詳情頁的技術指標深度展開
- 伺服器長期預警分析畫面

## 2. 頁面定位

此頁的核心定位是：

> 以單筆預警事件為主體，但依資料來源分成即時模式與歷史模式兩種前端呈現方式。

使用者進入此頁後，應能快速理解：

- 這筆預警是什麼
- 為什麼形成預警
- 現在或最終處於什麼狀態
- 風險等級到什麼程度

## 3. 資料來源分模型

即時預警顯示頁不應強迫即時資料與歷史資料共用完全相同的欄位。

### 3.1 即時預警資料

來源：

- 本地預警分析模組

特性：

- 預警仍在發生
- 內容可能持續更新
- 需要顯示「目前」資訊

建議欄位：

```text
alert_id
alert_type
status
current_severity_level
max_severity_level
first_occurred_at
updated_at
reason_summary
summary_description
indicator_summary
```

### 3.2 歷史預警資料

來源：

- 伺服器回傳的歷史預警資料

特性：

- 預警已完成
- 內容固定
- 不需要顯示「目前」資訊

建議欄位：

```text
alert_id
alert_type
final_status
max_severity_level
first_occurred_at
resolved_at
reason_summary
summary_description
indicator_summary
```

### 3.3 分模型原則

- 即時模式看「目前」
- 歷史模式看「結果」
- 共用同一頁面結構
- 不共用完全相同欄位

## 4. 進入方式

此頁目前有兩個入口。

### 4.1 儀表板健康狀態卡

規則：

- 只有當儀表板健康狀態卡顯示預警時，點擊後才導向此頁
- 若健康狀態卡顯示健康，則不導向此頁

資料來源：

- 目前正在發生的即時預警資料

對應模式：

- 即時模式

### 4.2 預警紀錄頁的歷史項目

規則：

- 使用者可從預警紀錄頁點擊某一筆歷史預警進入此頁
- 頁面應固定渲染該筆歷史資料
- 不切回目前其他正在發生的即時預警

資料來源：

- 伺服器歷史預警資料

對應模式：

- 歷史模式

## 5. 渲染模式

### 5.1 即時模式

適用情境：

- 從儀表板健康狀態卡進入
- 且目前存在進行中的預警

顯示原則：

- 頁首標題顯示 `即時預警`
- 顯示 `status`
- 顯示 `current_severity_level`
- 可附帶顯示 `max_severity_level`
- 顏色主題依 `current_severity_level` 決定

### 5.2 歷史模式

適用情境：

- 從預警紀錄頁點入單筆歷史預警

顯示原則：

- 頁首標題顯示 `預警詳情`
- 顯示 `final_status`
- 顯示 `max_severity_level`
- 不顯示 `status`
- 不顯示 `current_severity_level`
- 顏色主題依 `max_severity_level` 決定

## 6. 畫面結構

頁面由上到下分成兩個主區塊：

```text
1. 上區塊：主視覺與摘要區
2. 下區塊：預警資訊區
```

視覺原則：

- 邏輯上分成上下兩區
- 視覺上採貼合式銜接
- 上區與下區不是完全分離的兩張卡

## 7. 上區塊

上區塊承接主視覺內容，包含：

- 頁首標題
- 異常摘要區
- 摘要說明卡

### 7.1 頁首標題

- 即時模式：`即時預警`
- 歷史模式：`預警詳情`

### 7.2 異常摘要區

此區塊保留主標：

```text
發現異常指標
```

副句用來補充整體語意，例如：

- 綜合生理指標顯示異常變化
- 多項指標持續偏離目前正常狀態

此區塊的目的不是攤開分析規則，而是讓使用者一眼知道：

- 有異常
- 這次異常是綜合判斷結果

### 7.3 摘要原因區

摘要原因區用簡化卡片呈現主要異常因素，例如：

```text
HR ↑
上升

HRV ↓
下降

SpO2 ↓
持續下降
```

必要時可補短句上下文，例如：

- 低活動下
- 與目前活動情境不符

### 7.4 摘要說明卡

摘要說明卡以自然語言補充預警形成脈絡，例如：

```text
系統根據最近一分鐘資料判定，目前在低活動狀態下，心率上升、心率變異下降，且血氧持續下降，因此形成即時預警。
```

此區塊用來補足摘要原因區無法完整表達的語意。

## 8. 下區塊

下區塊承接正式預警資訊，以固定欄位呈現。

此區塊不應先定義一組共同欄位，再由不同模式把資料硬填入；應直接依模式各自定義渲染欄位。

### 8.1 即時模式欄位

即時模式建議顯示：

- 預警類型
- 目前狀態
- 目前風險等級
- 最高等級
- 開始發生時間
- 更新時間

欄位對應如下：

| 顯示欄位 | 資料來源 |
| --- | --- |
| 預警類型 | `alert_type` |
| 目前狀態 | `status` |
| 目前風險等級 | `current_severity_level` |
| 最高等級 | `max_severity_level` |
| 開始發生時間 | `first_occurred_at` |
| 更新時間 | `updated_at` |

### 8.2 歷史模式欄位

歷史模式建議顯示：

- 預警類型
- 最終狀態
- 最高等級
- 開始發生時間
- 解除時間

欄位對應如下：

| 顯示欄位 | 資料來源 |
| --- | --- |
| 預警類型 | `alert_type` |
| 最終狀態 | `final_status` |
| 最高等級 | `max_severity_level` |
| 開始發生時間 | `first_occurred_at` |
| 解除時間 | `resolved_at` |

## 9. 顯示等級與顏色規則

前端不直接將原始 `risk_score` 顯示給使用者，而是先轉成三個顯示等級：

- `輕度`
- `中度`
- `高度`

### 9.1 risk_score 對應規則

建議轉換如下：

```text
0 ~ 4   -> 輕度
5 ~ 6   -> 中度
7 以上  -> 高度
```

### 9.2 顏色主題對應

建議固定對應如下：

```text
輕度 -> 綠色
中度 -> 橙色
高度 -> 紅色
```

### 9.3 顏色套用原則

主色應影響：

- 上區塊背景
- 異常摘要區圖示與強調色
- 等級標籤
- 下區塊中的等級強調文字

歷史列表則只做輕量套用，例如：

- 等級 chip
- 類型小標
- 詳情入口色

### 9.4 共用轉換函式

前端應有共用函式，概念流程如下：

```text
risk_score
-> display_severity_level
-> color_theme
-> UI rendering
```

其中：

- `display_severity_level` = `輕度 / 中度 / 高度`
- `color_theme` = 前端主題色、背景色、標籤色、強調色

## 10. 狀態與等級分離原則

前端應明確區分以下概念：

- `status`
- `current_severity_level`
- `max_severity_level`

其意義如下：

- `status`：即時模式下的生命週期狀態
- `current_severity_level`：即時模式下的目前等級
- `max_severity_level`：該筆預警曾達到的最高等級

歷史模式下：

- 不顯示 `status`
- 改顯示 `final_status`
- 等級只顯示 `max_severity_level`

補充：

- 前端不使用 `未處理` 作為顯示狀態
- 前端狀態應以生命週期語意為主，例如：
  - `觀察中`
  - `注意`
  - `警戒`
  - `恢復中`
  - `已解除`

## 11. 導向規則

- 當存在進行中的即時預警時，儀表板可導向此頁
- 當該筆即時預警結束後，儀表板不再導向該筆預警
- 若使用者已停留在頁面中，不強制導回儀表板
- 若使用者從歷史紀錄頁進入，頁面固定渲染該筆歷史資料，不受當下即時預警狀態影響

## 12. 核心摘要

```text
即時預警顯示頁共用同一頁面結構，但依資料來源分成即時模式與歷史模式。
即時模式使用本地預警分析資料，顯示目前狀態與目前風險等級。
歷史模式使用伺服器歷史預警資料，顯示最終狀態與最高等級。
前端不直接顯示 risk_score，而是先轉成輕度 / 中度 / 高度，再決定主色與渲染方式。
```

最簡短版本如下：

> 即時預警顯示頁以單筆預警事件為核心，頁面分為上下兩區：上區塊顯示異常摘要與說明，下區塊顯示正式預警資訊；即時模式看目前狀態與目前等級，歷史模式看最終狀態與最高等級，兩者共用頁面結構但不共用完全相同欄位。
