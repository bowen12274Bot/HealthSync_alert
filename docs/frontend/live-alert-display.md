# 即時預警顯示設計

## 1. 文件目的

本文定義手機前端「即時預警頁」的顯示方式，作為：

- 單筆正在發生的預警畫面
- 儀表板導向即時預警頁的規則
- 前端預警資訊呈現格式

的設計依據。

本文件目前只處理：

- 正在發生的單筆即時預警
- 主資訊與摘要原因的顯示方式

本文件目前不處理：

- 預警歷史列表
- 預警詳情頁的完整技術指標展開
- 長期預警畫面

## 2. 頁面定位

即時預警頁只顯示：

> 目前正在發生的單筆即時預警。

這個頁面的目標不是一次列出所有預警，而是讓使用者在最短時間內知道：

- 現在發生什麼異常
- 為什麼會形成預警
- 目前的狀態與風險程度

補充：

- 此頁面本質上是一個即時渲染區塊
- 當存在正在發生的預警時，頁面可依當下資料持續更新
- 但若是從歷史預警紀錄點入，則應依該筆歷史紀錄內容渲染，而不是切回目前即時預警資料

## 2.1 進入方式

即時預警頁目前有兩個入口：

### 1. 儀表板健康狀態卡

規則：

- 只有當儀表板健康狀態卡目前顯示為預警狀態時，點擊後才導向即時預警頁
- 若健康狀態卡目前顯示為健康狀態，則不導向即時預警頁

此入口的頁面資料來源為：

- 目前正在發生的即時預警資料

### 2. 預警紀錄頁的預警項目

規則：

- 使用者可從預警紀錄頁點擊某一筆預警項目進入此頁
- 此時頁面應依該筆預警歷史紀錄渲染
- 不應切換成當下其他正在發生的即時預警資料

此入口的頁面資料來源為：

- 被點擊的那一筆歷史預警資料

## 2.2 渲染模式

因此此頁面需支援兩種渲染模式：

### 1. 即時模式

適用於：

- 從儀表板健康狀態卡進入
- 且目前存在正在發生的即時預警

特性：

- 頁面內容可依目前預警狀態持續更新
- 顯示的是當下進行中的預警事件

### 2. 歷史模式

適用於：

- 從預警紀錄頁點入某一筆預警項目

特性：

- 頁面內容固定以該筆歷史紀錄為準
- 不依賴當下是否仍有其他即時預警存在
- 不切回目前即時預警資料

## 3. 畫面結構

頁面由上到下分成兩個主區塊：

```text
1. 上區塊（主視覺與摘要區）
2. 下區塊（預警資訊區）
```

其中：

- 上區塊承接橘色主視覺區，內含頁首標題、異常摘要區與摘要說明卡
- 下區塊承接固定欄位資訊，顯示預警類型、狀態、風險分數與時間資訊

## 4. 上區塊

上區塊是即時預警頁的主視覺區，包含：

- 頁首標題
- 異常摘要區
- 摘要說明卡

此區塊應以同一組主色系統呈現，並依風險分數切換視覺色調。

## 5. 頁首標題

- 頁面標題為：`即時預警`
- 整體視覺節奏延續目前前端風格

## 6. 異常摘要區

異常摘要區位於頁面上半部，延續目前概念圖的閱讀方式。

此區塊保留大標：

```text
發現異常指標
```

副句可用來補充這次預警的整體語意，例如：

- 綜合生理指標顯示異常變化
- 多項指標持續偏離目前正常狀態

此區塊的目的不是完整解釋演算法，而是讓使用者一眼知道：

- 目前確實有異常
- 這次異常是綜合判斷，不是單一數值超標

## 7. 摘要原因區

摘要原因區位於異常摘要區內，用簡化卡片呈現本次預警的主要異常因素。

此區塊不是純文字長句，而是簡單、快速可讀的視覺摘要。

例如：

```text
HR ↑
上升

HRV ↓
下降

SpO2 ↓
持續下降
```

若需要，可補充簡短上下文，例如：

- 低活動下
- 與目前活動狀態不符

這塊的角色是把原本的綜合摘要，例如：

```text
低活動下 HR 上升、HRV 下降、且 SpO2 持續下降
```

改用更容易一眼理解的圖像化方式呈現。

## 8. 摘要說明卡

在摘要原因區下方，放一張摘要說明卡，以自然語言說明這次預警的判斷脈絡。

例如：

```text
系統根據最近一分鐘資料判定，目前在低活動狀態下，心率上升、心率變異下降，且血氧持續下降，因此形成即時預警。
```

這張卡的目的：

- 補足異常摘要區無法表達的完整語意
- 提供使用者可讀、可理解的判斷說明
- 不直接攤開所有分析規則細節

## 9. 下區塊

下區塊為固定欄位資訊區，承接正式預警資訊。

## 10. 預警資訊區

頁面下半部為固定欄位資訊區，建議至少包含：

- 預警類型
- 目前狀態
- 風險等級
- 開始發生時間
- 更新時間

這區塊的角色是：

- 提供正式、穩定、可對照的預警資訊
- 讓使用者知道目前這筆事件的狀態與時間脈絡

## 11. 顏色規則

即時預警頁的主色不應固定為單一橘色，而應依風險分數切換。

建議至少支援三組主色：

- 綠色：低風險或已明顯緩解
- 橙色：中度風險或注意狀態
- 紅色：高風險或警戒狀態

主色應一致影響：

- 上區塊背景色
- 異常摘要區圖示與強調色
- 風險分數或狀態標示

顏色切換依據以 `risk_score` 為主，不直接綁死於單一 `status` 文案。

## 11.1 顯示等級轉換

前端不直接以原始 `risk_score` 呈現所有顏色差異，而是先轉成三個顯示等級：

- `輕度`
- `中度`
- `高度`

這三個等級的用途是：

- 統一即時預警頁與歷史預警列表的視覺語意
- 提供使用者可理解的風險強度分級
- 讓顏色渲染規則集中於單一邏輯

補充：

- 前端畫面不直接顯示原始 `risk_score`
- 使用者看到的是 `輕度 / 中度 / 高度`
- `risk_score` 保留作為前端內部判斷顏色與顯示等級的依據

## 11.2 risk_score 對應規則

建議以前端共用規則將 `risk_score` 轉成顯示等級：

```text
0 ~ 4   -> 輕度
5 ~ 6   -> 中度
7 以上  -> 高度
```

這個對應的目的不是取代原始 `risk_score`，而是：

- 保留原始分數細節
- 同時提供穩定、簡化的前端視覺分級

## 11.3 顏色主題對應

前端等級與主色建議固定對應如下：

```text
輕度 -> 綠色
中度 -> 橙色
高度 -> 紅色
```

這組顏色對應應作為前端共用規則，供：

- 即時預警頁
- 預警歷史列表

共同使用。

## 11.4 共用顏色對應函式

前端應提供一個共用函式，先將 `risk_score` 轉為顯示等級，再由顯示等級轉換成畫面主題。

概念流程如下：

```text
risk_score
-> severity_level
-> color_theme
-> UI rendering
```

其中：

- `severity_level`：`輕度 / 中度 / 高度`
- `color_theme`：對應的文字色、背景色、強調色、標籤色

這個函式不需要在本文件中定義實作碼，但應作為前端共用規則存在。

## 11.5 即時預警頁的套用方式

即時預警頁的顏色主題應套用在：

- 上區塊主背景色
- 異常摘要區的圖示與強調文字
- 狀態標籤
- 風險分數強調色
- 摘要原因區與重點資訊區的主色點綴

套用方式應採：

- 淡色背景
- 主色強調

而不是整頁大面積純色塗滿，以維持與儀表板一致的卡片式視覺語言。

## 11.6 歷史預警列表的套用方式

歷史預警列表中的顏色套用應比即時預警頁更輕量。

建議套用在：

- 等級標籤
- 類型小標
- 左側圖示或標記點
- 詳情入口的強調色

歷史列表的目的在於快速掃描，不應因過度著色而影響閱讀密度。

## 11.7 等級與狀態分離原則

前端需要區分：

- `status`
- `severity_level`

其中：

- `status` 表示預警生命週期階段
- `severity_level` 表示前端顯示強度

例如：

```text
status = 觀察中 / 注意 / 警戒 / 恢復中 / 已解除
severity_level = 輕度 / 中度 / 高度
```

顏色主題應以 `severity_level` 為主，而不是直接由 `status` 決定。

補充：

- 前端 `status` 不使用 `未處理`
- `未處理` 可作為系統流程或後端欄位概念存在
- 但前端顯示應以預警生命週期狀態為主

## 12. 前端資料格式

即時預警頁至少需要以下資料：

```text
alert_type
status
severity_level
first_occurred_at
updated_at
reason_summary
summary_description
indicator_summary
```

欄位建議用途如下：

| 欄位 | 用途 |
| --- | --- |
| `alert_type` | 顯示預警類型 |
| `status` | 顯示目前狀態 |
| `severity_level` | 顯示風險等級（輕度 / 中度 / 高度） |
| `first_occurred_at` | 顯示開始發生時間 |
| `updated_at` | 顯示最後更新時間 |
| `reason_summary` | 異常摘要區的整體主概念 |
| `summary_description` | 摘要說明卡的自然語言內容 |
| `indicator_summary` | 橘色摘要原因區的簡化異常指標列表 |

## 13. 導向規則

當前端存在進行中的即時預警時：

- 儀表板可導向此頁

當該筆預警結束後：

- 儀表板不再導向該筆即時預警
- 但若使用者已停留在此頁，不強制導回儀表板
- 若使用者是從歷史預警紀錄點入，則頁面維持渲染該筆歷史資料，不受當下即時預警導向規則影響

也就是：

- 取消入口導向
- 不中斷使用者目前瀏覽

## 14. 核心設計原則

即時預警頁的核心原則如下：

- 上區塊先用大標與摘要原因區讓使用者一眼知道異常重點
- 再用摘要說明卡補足自然語言解釋
- 下區塊再用固定欄位顯示正式預警資訊
- 主色依 `risk_score` 轉換後的顯示等級切換，不固定為單一橘色

最簡短總結如下：

> 即時預警頁以單筆正在發生的預警為核心，畫面分成上下兩個主區塊：上區塊承接頁首標題、異常摘要區與摘要說明卡，並以 HR 上升、HRV 下降、SpO2 持續下降等簡化卡片呈現主要異常；下區塊則以固定欄位顯示預警類型、目前狀態、風險分數、開始發生時間與更新時間。頁面主色應依 `risk_score` 在綠、橙、紅之間切換，預警結束後只取消儀表板導向，不強制將使用者從頁面帶離。
