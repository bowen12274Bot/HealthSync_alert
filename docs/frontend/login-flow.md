# 登入流程設計

## 1. 文件目的

本文定義手機前端的登入流程與登入初始化規則，作為以下內容的共同依據：

- 登入頁行為
- 登入成功後的放行條件
- `activity_baseline_profile` 初始化流程
- baseline 初始化失敗時的前端處理方式

本文只處理前端登入與初始化放行流程，不處理：

- 帳號註冊流程
- 忘記密碼流程
- baseline API 實作細節
- baseline 自動學習規則

## 2. 流程定位

本專案的登入流程不只處理帳號驗證，也要完成本地預警所需的初始化資料準備。

核心原則如下：

> 只有當帳號驗證成功，且 `activity_baseline_profile` 已成功取得並保存到本地後，才視為登入初始化完成並進入主頁面。

原因如下：

- 本地模擬資料生成需要 baseline
- 本地預警分析需要 baseline
- baseline 屬於可離線使用但需由伺服器提供的必要資料

因此：

- 單純帳密正確，不代表可以直接進入主頁
- 還需要完成 baseline 初始化

## 3. 登入流程

### 3.1 正常流程

建議流程如下：

```text
1. 使用者輸入帳號密碼
2. 前端送出登入請求
3. 帳號驗證成功
4. 前端同步嘗試取得 activity_baseline_profile
5. baseline 成功保存到本地
6. 放行進入主頁面
```

### 3.2 放行條件

只有在以下兩個條件都成立時，才可進入主頁面：

- 帳號驗證成功
- baseline 初始化成功

也就是：

```text
login success
+ baseline success
= allow enter app
```

## 4. baseline 初始化失敗時的處理

若帳號驗證成功，但 baseline 取得失敗，則不直接進入主頁面。

前端建議處理如下：

- 畫面仍停留在登入頁
- 顯示登入初始化中的狀態
- 系統每 5 秒自動重試取得 baseline
- baseline 一旦成功保存到本地，立即自動放行進入主頁面

概念流程如下：

```text
1. 帳號驗證成功
2. baseline 取得失敗
3. 停留在登入頁
4. 每 5 秒重試 baseline
5. baseline 成功後自動進入主頁
```

## 5. 前端狀態建議

登入頁至少可區分以下幾種狀態：

- 尚未送出登入
- 帳號驗證中
- baseline 初始化中
- baseline 初始化失敗，等待自動重試

顯示文案可採以下方向：

- `正在驗證登入資訊...`
- `登入成功，正在初始化個人基準資料...`
- `基準資料取得失敗，系統將自動重試...`

## 6. baseline 在前端的角色

`activity_baseline_profile` 在前端的角色，不是一般暫時資料，而是：

- 由伺服器提供
- 保存於本地
- 供離線模擬與本地預警分析共同使用

因此前端應將其視為：

> 可離線使用的必要初始化資料。

本階段不處理：

- 手機端自行學習並更新 baseline
- baseline 本地自主生成

目前規則如下：

- baseline 以伺服器端提供為主
- 前端只負責取得、保存與使用

## 7. 核心摘要

```text
登入流程分為兩步：先完成帳號驗證，再完成 baseline 初始化。
只有帳號驗證成功且 baseline 已成功保存到本地後，才放行進入主頁面。
若 baseline 初始化失敗，畫面停留在登入頁並每 5 秒自動重試，成功後再自動放行。
```

最簡短版本如下：

> 本專案的登入不只驗證帳號，還必須完成 `activity_baseline_profile` 初始化；只有帳號驗證成功且 baseline 已取得並保存到本地後，才進入主頁，若 baseline 失敗則停留在登入頁自動重試。
