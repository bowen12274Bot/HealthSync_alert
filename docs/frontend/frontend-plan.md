# Frontend Plan

## 1. 目的

這份文件整理目前手機前端的主導航與各頁顯示重點，作為前端骨架實作的基礎。

目前放在 `docs/frontend/` 的概念圖可作為版面與視覺方向參考，但正式前端實作與後續設計調整仍以本文件內容為主。

相關子文件：

- [即時預警顯示設計](./live-alert-display.md)

## 2. 主導航

底部導覽先規劃四個主頁：

- 儀表板
- 趨勢報表
- 預警紀錄
- 設定

對應概念圖：

- [儀表板概念圖](./dashboard-overview-concept.png)
- [趨勢報表概念圖](./trends-report-concept.png)
- [預警紀錄概念圖](./alert-records-concept.png)
- [設定概念圖](./settings-concept.png)

原則：

- 主導航依照功能分，不依照短期 / 長期分
- 短期 / 長期放在頁內處理，不放到底部主導航

## 3. 各頁重點

### 3.1 儀表板

定位：總覽目前狀態。

顯示內容：

- 頂部標題
- 右上角使用者頭像入口
- 上方固定通知卡
- 即時健康數值卡片
- 最下方連線 / 離線與同步狀態

通知卡規則：

- 健康狀態與警戒狀態共用同一張卡片
- 平常顯示健康狀態與持續健康時間
- 異常時顯示警告摘要與導向入口
- 點擊後導向即時預警頁

健康數值卡片：

- 心率
- 血氧
- HRV

系統狀態：

- 離線時顯示離線狀態
- 連線時顯示連線狀態與上次同步時間

補充：

- 不放預警詳細內容
- 使用者頭像只放在儀表板
- 點擊頭像後導向個人資料頁

### 3.2 趨勢報表

定位：顯示健康資料變化與報表。

目前規劃：

- 先做版面骨架
- 頁內處理短期與長期資料
- 暫不定圖表與資料細節

### 3.3 預警紀錄

定位：集中顯示預警資訊。

補充原則：

- 預警相關頁面應共用同一套風險分數顯示等級與顏色對應規則
- `risk_score` 應先轉成 `輕度 / 中度 / 高度`
- 該規則同時適用於即時預警頁與歷史預警列表
- 前端畫面顯示風險等級，不直接顯示原始風險分數
- 前端狀態顯示以預警生命週期狀態為主，不使用 `未處理`
- 即時預警資料與歷史預警資料視為兩種不同來源的前端模型，不強求共用完全相同欄位

#### 3.3.1 即時預警

顯示內容：

- 即時預警畫面

補充：

- 單筆即時預警的畫面結構、導向規則與顯示內容，另見 [即時預警顯示設計](./live-alert-display.md)
- 即時預警是當下的預警畫面，不用列表呈現
- 即時預警資料來源為本地分析模組
- 即時預警頁應顯示當前欄位，例如目前狀態、目前風險等級、最高等級、開始發生時間與更新時間

#### 3.3.2 歷史紀錄

顯示內容：

- 歷史預警列表
- 篩選條件
- 預警詳情入口

補充：

- 歷史紀錄使用預警列表呈現
- 預警詳情頁由歷史紀錄列表點入
- 歷史紀錄頁只顯示來自伺服器的歷史預警資料
- 歷史紀錄不顯示目前狀態與目前風險等級這類即時欄位
- 歷史紀錄摘要以最高等級為主，並搭配發生時間、解除時間或類型摘要呈現

### 3.4 設定

定位：管理個人與系統相關功能。

顯示內容：

- 個人資料
- 通知設定
- 同步設定
- 關於系統
- 登出

補充：

- 個人資料頁與設定中的個人資料入口是同一頁
- 儀表板右上角頭像只是快捷入口

## 4. 目前已確認原則

- 儀表板只放總覽，不放預警詳細內容
- 預警詳細內容由即時預警頁與歷史預警詳情承接
- 趨勢報表先流版面，不先定細節
- 預警種類先以清楚標示為原則，細節後補
- 即時預警頁看「現在」，歷史預警頁看「結果」
