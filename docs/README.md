# Docs Guide

## 1. 這份文件在說什麼

這份文件用來說明 `docs/` 下面各份文件的用途，幫助組員快速找到目前的系統方向與後續待做事項。

## 2. 建議閱讀順序

建議先用下面順序開始：

1. `docs/architecture.md`
2. `docs/setup/README.md`
3. `docs/project-scope.md`
4. `docs/database/README.md`
5. `docs/api/README.md`
6. `docs/alert-rules/README.md`

## 3. 文件分工

- `architecture.md`：目前系統架構總覽
- `project-scope.md`：專案目標、使用情境與後續方向
- `database/README.md`：雙層資料庫規劃與資料表方向
- `api/README.md`：API 分類與預計端點
- `alert-rules/README.md`：即時預警與長期預警方向
- `setup/README.md`：開發與測試環境入口
