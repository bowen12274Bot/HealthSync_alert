# 伺服器長期資料保存實作計畫

此計畫旨在為 HealthSync_alert 專案實作後端長期資料庫模型、資料初始化播種（Seeding），並更新同步 API。

## 1. 核心亮點

1. **5 張全新 SQLAlchemy 2.0 資料模型**：完全符合《Server Database Spec》的欄位標準與關係設計。
2. **雙重標識去重與關聯機制**：`user_id`（String，由伺服器自動以 `user_{user_account_id}` 形式填充以與 SQLite 對齊）與 `user_account_id`（Integer，與後端登入帳號 FK 關聯）並存，保障高度擴充性與同步順暢度。
3. **完整預警資料同步入庫**：實作 `POST /sync/batch` 中預警歷史資料 (`alerts`) 的 `ON CONFLICT DO NOTHING` 冪等 Upsert。
4. **自動初始化 Seeding**：在啟動時為初始的系統管理員帳號自動生成對應的 `UserProfile` 與活動等級 0~3 的 `UserActivityBaseline` 基準值。

## 2. 實作細節

### [後端資料庫模型實作]

於 `server/app/models/` 建立 5 個模型：

- `user_profile.py`: 實作 `UserProfile` 模型，保存使用者個人基本健康資料。
- `user_activity_baseline.py`: 實作 `UserActivityBaseline` 模型，保存不同活動等級 (0~3) 下正常生理基準值。
- `daily_health_summary.py`: 實作 `DailyHealthSummary` 模型，保存每日健康狀態摘要。
- `long_term_alert.py`: 實作 `LongTermAlert` 模型，保存後端長期分析模組產生的長期預警。
- `alert_history.py`: 實作 `AlertHistory` 模型，保存手機同步上傳的預警資料。

更新現有模組：
- `user_account.py`: 掛載與 `UserProfile` 的一對一關聯屬性。
- `database.py`: 於 `create_db_tables` 中動態加載新建立的 5 個 Model 模組以確保系統啟動時順利完成建表。

### [後端資料庫初始化播種 (Seeding)]

於 `seed.py` 中：
在自動播種預設管理者帳號的同時，為其建立一組 `UserProfile` 預設檔案，以及分別對應活動等級 0、1、2、3 的 `UserActivityBaseline` 基準值（如靜止、輕度、中度、劇烈活動之生理極限）。

### [同步 API 與 Pydantic 驗證格式更新]

於 `sync.py` 中：
1. **Pydantic Schema 設計**：擴充 `SyncBatchRequest` 中的 `alerts` 欄位以支援 `list[AlertSyncSchema]`，且移除 `user_id` 欄位，由後端藉由 JWT Token 安全校驗身分歸屬。
2. **Transaction 寫入與去重邏輯**：
   - 解析上傳的 `alerts` 陣列，並確保 Foreign Key 滿足限制。
   - 運用 PostgreSQL `ON CONFLICT (alert_id) DO NOTHING` 的批次 Upsert 機制，完成預警歷史的高效、冪等同步。
   - 補齊時間欄位之 UTC 與時區驗證（未帶時區或非 UTC 即回傳 `400`），並針對 `window_start < window_end`、`sample_count >= 0`、預警狀態歷程、解除狀態一致性等進行嚴格的後端語意校驗。
