# HealthSync 同步系統端到端 (E2E) 測試指南

為了驗證「5秒高頻採集 -> 10分鐘打包壓縮 -> 隨機延遲同步 -> 後端防重冪等寫入」的完整二進制資料流，我們不需要傻傻等待 10 分鐘。本指南將引導你透過**調整排程參數**來進行「快速驗證測試」。

---

## 第一步：修改前端參數以進行「快速測試」

請暫時修改以下兩個檔案的參數，將 10 分鐘的等待時間縮短至幾秒鐘：

### 1. 修改排程器時間 (`mobile-app/src/modules/health-simulation/engine/schedule.ts`)
將採樣改為 1 秒一次，打包改為 15 秒一次：
```typescript
// 搜尋這兩行並修改：
const GENERATION_INTERVAL_MS = 1_000 // 原為 5_000 (改為 1 秒生成一筆)
const PACK_INTERVAL_MS = 15_000    // 原為 10 * 60 * 1000 (改為 15 秒打包一次)
```

### 2. 修改隨機同步延遲 (`mobile-app/src/modules/health-simulation/engine/sync_client.ts`)
將隨機延遲 (Jitter) 改為 0 秒，以便打包完立刻上傳：
```typescript
// 搜尋這行並修改：
const jitterMs = 0 // 原為 Math.floor(Math.random() * 600 * 1000) (取消延遲，方便測試)
```

---

## 第二步：啟動並準備後端環境 (使用 Docker)

因為我們修改了 `server/requirements.txt`，後端 API 容器**必須重新編譯**以安裝 `msgpack` 與 `zstandard` 套件。

1.  **切換到專案根目錄**：
    確保你在 `HealthSync_alert` 專案根目錄下（即含有 `docker-compose.yml` 的地方）。

2.  **以 `--build` 參數啟動 Docker Compose**：
    執行以下指令重新編譯並啟動後端服務與 PostgreSQL 資料庫：
    ```bash
    docker compose up --build
    ```
    *啟動成功後，FastAPI 與 PostgreSQL 會運行在 Docker 容器中。`create_db_tables` 也會在容器啟動時自動跑完，完成資料表建立。*

---

## 第三步：啟動前端與觀察測試

1.  **啟動前端 App**：
    開啟另一個終端機，切換到 `mobile-app` 目錄並啟動：
    ```bash
    cd mobile-app
    npm run dev
    ```

2.  **開啟瀏覽器開發者工具 (F12)**：
    進入 Console 視窗，準備觀察日誌。

3.  **啟動模擬器生成**：
    在 App UI 上開啟健康模擬器（啟動後，Scheduler 會開始工作）。

4.  **觀察 Console 日誌流**：
    *   **第 1~15 秒**：感測器每秒寫入一筆 realtime 資料到本地 SQLite。
    *   **第 15 秒**：觸發 `packPendingWindows`，你會看到 WASM ZSTD 壓縮引擎啟動並將資料寫入本地 `periodic_health_records`。
    *   **緊接著**：SyncClient 啟動，Console 印出：
        `[SyncClient] 準備同步，隨機延遲 0 秒...`
    *   **同步成功後**：Console 印出：
        `[SyncClient] 同步成功：已上傳並更新 1 筆資料狀態`

## 第四步：驗證資料庫與冪等性

### 1. 後端資料庫驗證 (PostgreSQL 容器)
由於資料庫跑在 Docker 內，你可以透過以下指令直接進入 PostgreSQL 容器內進行 SQL 查詢：
```bash
docker exec -it healthsync-postgres psql -U healthsync_user -d healthsync_alert
```
進入 psql 後，執行查詢：
```sql
SELECT id, user_id, window_start, window_end, avg_hr, sample_count, length(raw_data_payload) 
FROM periodic_health_records;
```
*   **驗證重點**：
    *   `sample_count` 應該大於等於 6（因為我們設定 15 秒打包一次，1 秒 1 筆）。
    *   `length(raw_data_payload)` 或內容應該顯示為非零二進制數據。這代表 MsgPack + ZSTD 的壓縮資料已完美封存入庫！

### 2. 測試冪等性 (Idempotent Test)
模擬網路重傳：
使用 API 工具 (如 Postman) 或 Python 腳本，對後端 `http://localhost:8000/api/sync/batch` 發送同一個 `window_start` 與 `window_end` 的 Payload 兩次。
*   **預期結果**：第一次回傳 `success=true` 且資料庫寫入；第二次同樣回傳 `success=true`，但後端資料庫透過 `ON CONFLICT DO NOTHING` 安全忽略，絕不拋出 `Duplicate Key` 錯誤，亦不會產生重複數據！

## 測試完畢後

驗證無誤後，**請務必將上述修改的參數還原**（`schedule.ts` 還原為 5秒/10分鐘，`sync_client.ts` 還原為隨機 0~599 秒延遲），即可提交上線！
